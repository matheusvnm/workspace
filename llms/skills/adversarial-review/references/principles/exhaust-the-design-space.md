# Exhaust the Design Space Before Committing

**Principle:** For decisions where the right answer isn't obvious, build 2–3 competing prototypes or sketches and compare them side-by-side before committing. Building the wrong thing costs far more than exploring options.

## When It Applies

- Novel architectural choices with multiple viable approaches.
- API or schema designs where downstream coupling is hard to reverse.
- Anything where constraints don't already pick the answer.

## When It Doesn't

- Mechanical work with an established pattern.
- Bug fixes or refactors with a clear target state.
